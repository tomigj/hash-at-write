================================================================================
READING THE WORD "inactive" ABOVE — REQUIRED CONTEXT
================================================================================

`systemctl is-active ssh` reports `inactive` on this host while SSH is fully
functional and port 22 is listening. That is not a failed step. Ubuntu 24.04
ships SSH socket-activated:

    $ systemctl list-unit-files | grep -iE '^(ssh|sshd)'
    ssh.service                                    disabled        enabled
    ssh.socket                                     enabled         enabled

    $ systemctl is-active ssh.socket ; systemctl is-enabled ssh.socket
    active
    enabled

    $ systemctl is-active ssh.service ; systemctl is-enabled ssh.service
    inactive
    disabled

    $ dpkg -l openssh-server | tail -1
    ii  openssh-server 1:9.6p1-3ubuntu13.19 amd64  secure shell (SSH) server, ...

`ssh.socket` holds the listener; `ssh.service` is spawned per connection and is
correctly inactive when nothing is connected. The socket is what is enabled and
what comes up at boot.

`ssh.service` being `disabled` is likewise correct and must not be "fixed".
Enabling it would conflict with the socket, disable socket activation, and move
this host off the distribution default -- changing a configuration that is
itself evidence, for a cosmetic status line.

================================================================================
IPv6
================================================================================

The listener above covers [::]:22 and this host has four globally routable IPv6
addresses with a default v6 route. The allow rule is IPv4-only, so inbound v6
SSH is denied -- but by the DEFAULT POLICY, which `ufw status numbered` does not
print. `ufw status verbose` prints it explicitly and is required in the capture
protocol for this reason.

is what makes the connectivity test produce a positive artifact -- see below.
